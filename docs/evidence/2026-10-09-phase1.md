## 复现命令与运行参数

命令在 Ubuntu Bash 仓库目录执行，运行脚本默认使用 `~/aerobase-runtime`：

```bash
# run-005：显式选择 Cyclone DDS RMW
RMW_IMPLEMENTATION=rmw_cyclonedds_cpp bash scripts/verify_sitl.sh \
  --output "$PWD/.runtime/evidence/run-005"

# run-006：覆盖 monitor 早于 PX4 启动
bash scripts/verify_sitl.sh --monitor-first \
  --output "$PWD/.runtime/evidence/run-006"
```

两次检查均使用 `MicroXRCEAgent udp4 -p 8888`、`HEADLESS=1 make -j4 px4_sitl gz_x500` 和 `ros2 run aerobase_monitor vehicle_monitor`。ROS domain 为 0，XRCE 传输使用 UDP 8888，模型为 `x500_0`，默认 stale timeout 为 3 秒、报告周期为 1 秒。测试脚本负责各进程环境并清理本次启动的进程。

## 观测结果

Gazebo 模型列表包含 `ground_plane` 和 `x500_0`。monitor 订阅四条 `/fmu/out` Topic；ROS 图中仅有 monitor 的内建日志和参数事件发布器，没有 `/fmu/in` 发布器或 PX4 命令服务客户端。监测恢复后显示 `connected`，状态为 `disarmed(1)`；该状态表示遥测更新，不表示飞控具备起飞能力。

run-006 恢复后的代表性输出：

```text
Vehicle: connected
Arming: disarmed(1)
Nav state: auto_loiter(4)
Failsafe: false
Position: (0.06, -0.03, 0.01) m [ned(1)]
Velocity: (0.02, -0.02, -0.01) m/s [ned(1)]
Battery: 100.0%, 16.20 V, unknown (id=1)
Global position: lat=47.3979714, lon=8.5461634, alt=0.24 m AMSL [WGS84]
```

仿真电池 current 字段无效，因此展示为 unknown。PX4 未连接地面站，日志记录相应 Preflight Fail；测试未为消除警告而关闭飞控检查。停止 Agent 后 monitor 显示 disconnected，Arming、Position 等字段变为 stale；重启 Agent 后恢复 connected。

## 失败与兼容性观察

- PX4 默认仿真插件需要 OpenCV 开发包；缺少该依赖时构建失败，依赖安装脚本已包含该包。
- Ubuntu 更新版 spdlog 与 Agent v2.4.3 的格式化接口不兼容；测试组合固定使用 spdlog v1.9.2。
- run-002 和 run-004 使用 Fast DDS ROS RMW 时发现接口但未收到遥测，最终超时。尝试 UDP-only 和调整启动顺序未解决该现象。
- run-001 和 run-003 在诊断期间加入 ROS CLI 参与者后取得数据，不作为独立验收结果。
- Cyclone DDS ROS RMW 下 run-005、run-006 两次独立检查通过。Fast DDS 现象根因未查明；这是该 WSL2 配置中的观察，不能推广为 Fast DDS 在其他环境中的普遍问题。

## 验收范围与证据位置

本报告覆盖 headless SITL 的仿真模型与遥测数据链路。没有验证实体飞控、真实传感器、真实飞行、任何飞行控制功能、Gazebo GUI 视觉表现或安全认证。单条必要遥测流故障由 Python 测试覆盖，未执行单流 SITL 故障注入。

运行原始结果位于本地忽略目录 `.runtime/evidence/run-001` 至 `run-006`，包括失败、诊断和通过记录。可提交的报告摘要及版本记录保存在本目录，保留运行 ID 供核对。
